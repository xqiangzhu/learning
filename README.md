## 2. 画图约定（重要，避免误读）

1. **联动 ≠ 已证实调用**。note 里的 `← / → / ↔ 某域某流` 是文档口径的"**评审时一起检查**"，**不表示已证明存在同步调用**。文档 §3、§4、§7 反复强调这一点，图中所有联动标注都按此理解。
2. **活动图里的 `fork` = 独立入口/出口路径**，不是真实并发。例如订单域的两条建单入口（体检 `ORD-01` / 商城 `ORD-02`）按文档"三套订单体系不合并"的原则画成并行分支。
3. **不虚构未证明的流程**。文档只写了查询/配置/后台入口的地方（如团单 `BEN-01` 生命周期、到检率口径 `Q8`），图上标注"待核/口径待核"，不补造状态机。
4. **边界红线**在图上以 note 显式标出，例如：
   - 报销 `APP-07` ≠ 退款 `ORD-04` ≠ 理赔 `FUL-04`（三条状态机分开审）
   - 地址只存快照 `ORD-08`，通用地址簿主数据在 `U01`（九域外）
   - 门店评价依附预约 `APP-08`，不因页面位置归供应商域

## 3. 渲染方式

需要 Java + PlantUML（本机已放 `tools/plantuml.jar`）：

```bash
# 渲染全部为 PNG
java -jar tools/plantuml.jar -charset UTF-8 -o ./preview ./*.puml

# 终端 ASCII 版（无图形环境时）
java -jar tools/plantuml.jar -charset UTF-8 -utxt -o ./ascii ./*.puml

# 单个文件
java -jar tools/plantuml.jar -charset UTF-8 -o ./preview ORD-订单域-业务流.puml
```

**字体**：图内用 `skinparam defaultFontName "Microsoft YaHei"`，Windows 下直接可用；Linux 渲染请改成 `Noto Sans CJK SC` 之类已安装的中文字体，否则中文会变方框。
**字符**：避免使用 `⇄` 等字体覆盖不全的符号（会渲染成方框），本目录统一用 `← → ↔`。

## 4. 编号索引

- `ORD-xx` / `APP-xx` 等：**本文档十域流 ID**（§3），可在源文档全文搜索。
- `Fxx`：源文档 §6 给原文 33 条流加的检索编号。
- `Gxx`：源文档 §7 给图谱 77 条 flow 的编号（旁边 `flow:...` 是可在 `domain-graph.json` 精确搜索的 ID）；`①—⑧` 是该流按 `weight` 升序的步骤序号。
- `U01`~`U10`：已闭合的归属决议编号（§5.1）；`T01`~`T04`：技术承载标签（§5.3），**不是业务域**。
