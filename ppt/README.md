# 体检系统升级 V2 · 领域术语表 PPT

把 `CONTEXT.md`（体检系统升级V2 领域术语表）转成可直接用于评审的演示文稿。
**一套内容模型 → 两个版本 × 两种产物**：`.pptx`（交付物）与网页速览版（可打印成 PDF 讲义）。

| 版本 | 页数 | 定位 |
|---|---|---|
| **10 页精简版** | 10 | **主交付物**：一次评审讲完，无导读/目录/章节页 |
| 23 页完整版 | 23 | 附录：逐术语展开，含导读、目录、章节页、速查表 ×2、ADR 索引、结尾页 |

---

## 1. 产物

| 文件 | 说明 |
|---|---|
| `slides/体检系统升级V2-术语与切流架构-10页.pptx` | **10 页 16:9，含每页演讲者备注**（约 81 KB） |
| `slides/体检系统升级V2-术语与切流架构-23页完整版.pptx` | 23 页完整版（约 132 KB） |
| `slides/index.html` | 10 页版网页速览（← → 翻页，`Ctrl/Cmd+P` 打印为 PDF） |
| `slides/full.html` | 23 页版网页速览 |

> `slides/` 是渲染产物目录（仓库根 `preview/` 同理）。目录名刻意避开 `dist/ build/ out/`，
> 那几个名字会被工作区快照忽略、不会持久化。

## 2. 重新生成

```bash
python3 -m venv .venv && .venv/bin/pip install python-pptx
.venv/bin/python build.py                 # 两个版本 + 两份网页速览，并打印自检报告
.venv/bin/python build.py --only compact  # 只构建 10 页精简版（或 --only full）
.venv/bin/python build.py --quiet         # 只在自检不通过时输出
```

`build.py` 退出码非 0 表示自检失败（文字溢出或形状越界），可直接当 CI 门禁。

本地看网页速览版：

```bash
python3 -m http.server 8000 --bind 0.0.0.0 --directory slides   # 打开 http://localhost:8000
```

## 3. 目录结构

| 文件 | 职责 |
|---|---|
| `deck_content.py` | **唯一事实来源**：14 个术语文案、配色/字体规范、拓扑图坐标；`SLIDES_FULL`（23 页）与 `SLIDES_COMPACT`（10 页）都在这里 |
| `render_pptx.py` | PPTX 渲染器（python-pptx 原生形状绘制，不依赖模板，产物完全可编辑） |
| `render_html.py` | 网页速览版渲染器（与 PPTX 共用同一套版面数学，1in = 96px） |
| `build.py` | 构建入口 + 版面自检 |

改内容只改 `deck_content.py`；改版式改对应 renderer。

**精简版不复制文案**：`SLIDES_COMPACT` 用 `dict(SLIDES_FULL[i], **覆盖)` 从完整版派生，
术语速查表的术语名/英文名/所属域、检查清单条目、ADR 索引行也都从完整版程序化取用，
因此改一处术语，两个版本同步生效。

## 6. 事实边界（重要）

CONTEXT.md 明确要求"仅收录领域术语定义，不包含临时实现细节"，因此：

1. **原文口径**：所有定义与数字（`10.142` / `10.20` 网段、`100:0`、`P95 恶化 <20%`、
   `≥1 个周期`、`CLUSTER_ZONE`）均逐条来自 CONTEXT.md，未作外推。
2. **标注为推导的内容**（页脚已注明，评审时可整页跳过）：
   - 切流时序 T1–T6 的**先后顺序**，按术语之间的依赖关系推导，非原文编号；
   - 落地检查清单，是术语口径的可执行化整理，不替代发布手册 SOP；
   - 完整版第 14 页"替代做法"，是 Expand & Contract 模式的直接推论；
   - 完整版第 07 页页脚"隔离责任落在注册中心 + 标签路由"，是原文两条术语的合并推论。
3. **不虚构**：ADR 正文未随 CONTEXT.md 提供，ADR 索引页的主题**按文件名**整理，
   不引用任何未在 CONTEXT.md 中出现的结论。

## 7. 版面自检是怎么做的

沙箱里没有 PowerPoint / LibreOffice，无法渲染截图，所以用两道程序化检查代替肉眼验收：

- **文字溢出**：按 em 宽度模型（全角 1.0em、大写 0.70em、数字 0.56em、小写 0.52em）
  估算每个文本框的行数与高度，和预留高度比对；表格单元格同样参与（PowerPoint 会按内容
  自动撑高行）。当前 **10 页版 219 个文本块 0 溢出、23 页版 403 个 0 溢出**（阈值 0）。
- **形状越界**：重新打开生成的 pptx，检查所有形状是否落在 13.333 × 7.5 in 画布内；
  封面/章节页有意出血的装饰圆环以 `deco-*` 命名并跳过。当前 **两版均 0 越界**。

字体统一写入 `a:latin` + `a:ea`（Microsoft YaHei），避免中文在部分环境下回退成宋体；
符号只用雅黑覆盖良好的 `· ● ▪ □ ■ × → ← ↔ ①②③`，不用 `⇄ ⚡` 这类会变方框的字符
（与仓库根 `README.md` 的画图约定一致）。
