# 4. 体检积分抵扣与子订单分摊落标 (Point Deduction and SubOrder Allocation)

系统锁定体检业务中积分与法定货币 **1:1 固定兑换比例**（1 积分 = 1 元），支持 100% 全额积分抵扣，并严格遵循“**先套餐升级，后自选加项**”的扣减顺序，将消耗的积分与自费现金精确分摊落标到对应子订单（`MEMBER_EWP_ORDER_SUB`）中。

## 背景与权衡

在企业健康管理中，企业雇员常使用福利积分对体检进行升舱（如补齐 300 元升级差价）或增购自费加项包（如 200 元胃镜）。在混合结算时，存在多种抵扣与记账方式的选择：
- **比例配置 vs 固定等值**：虽然 MIS 后台存在积分兑换比例配置字段，但在实际体检结算中浮动汇率极易造成财务结算对账混乱与发票金额开具争议；
- **主单笼统记账 vs 子订单精细落标**：若积分仅记录在主订单上，一旦发生加项退订或发票拆分，系统将无法溯源哪笔加项是由积分支付、哪笔是由个人现金支付。

## 架构决策

- **1:1 绝对等值兑换（Point Parity）**：
  - 核心结算引擎锁死 1 积分 = 1 元人民币，忽略后台浮动积分比例配置。
  - 对允许积分抵扣的项目（`packageIntegralLimit=01`），支持 100% 全额积分抵扣，不设置强制自费比例门槛。
- **法定抵扣优先级（Package-first Priority）**：
  - 混合支付时，积分优先用于抵扣主套餐升舱/加价差额（`02-升级套餐 / 03-加价套餐`）；
  - 剩余积分再按顺序扣减自选加项包（`01-加项套餐`）。
- **子订单精细落标（SubOrder Allocation）**：
  - 结算引擎不以主单作为唯一积分记账点，而是将抵扣后的积分值（`scoreValue`）与剩余应付现金（`payCurrencyValue`）精确分摊写入每个子订单（`EwpOrderSubBean`）；
  - 使得每个子项的支付构成（积分付了多少、现金付了多少）清晰可溯，为财务分账、发票开具与售后退款提供原子级数据支撑。
