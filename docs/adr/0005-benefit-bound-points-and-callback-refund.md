# 5. 积分履约与退款联动机制：资金回调驱动与下游权益对账 (Benefit-bound Points Lifecycle & Callback-driven Refund)

在混合支付（现金 + 积分）退款中，系统采用“**资金退款成功回调驱动下游积分释放**”的级序策略；同时确立“**积分生命周期严格依附于体检权益，积分总账由下游系统独立托管对账**”的架构定位。

## 背景与权衡

混合支付场景下的逆向退款涉及两个异构结算主体：法定货币资金通道（招行一网通/微信/支付宝）与虚拟积分中心（福粒/信福通/核心会员系统）。
若两边并发同步发起退款：
- 一旦现金退款因银行风控失败，而积分已先期返还，将导致严重的单边账损失；
- 若 HMSC 自行维护独立积分钱包总账，会与外部多租户福利平台的账户体系产生双写不一致与重复对账。

## 架构决策

- **资金回调驱动退积分（Callback-driven Point Refund）**：
  - 混合订单申请退款时，系统先向三方支付网关发起资金退款请求；
  - **积分退还严格挂载在资金退款成功的异步回调方法内部**，只有银行/网关确认钱已退回，才触发调用下游积分接口释放退还积分，形成“资金先退 ➔ 回调退积分”的一前一后异步联动；
  - **失败回滚与重试**：若退积分下游接口调用异常，回调事务主动抛出异常回滚，促使资金网关重新推送通知重试；超过最大重试阈值后，落标异常记录流转人工介入，绝不形成单边死账。
- **积分生命周期绑定权益（Benefit-bound Lifecycle）**：
  - 体检平台的业务运转完全以“权益（Benefit）”为中心，积分的时效与使用权严格受制于所属体检权益的起止有效期（Benefit Validity Period），平台不设脱离权益的独立积分时钟。
- **总账下沉下游与两阶段对账（External Points Ledger）**：
  - 积分账户真值与资产总账全部下沉至下游外部系统（福粒、信福通等），HMSC 仅定位为积分消费者与交易调度方；
  - 正向交易执行“**下单预冻结 ➔ 支付回调转实扣**”；
  - 逆向流转执行“**取消待付原路释放 ➔ 退款回调通知解冻**”；
  - 外部系统依据权益分配的积分流水进行账目审计与资金核对。
