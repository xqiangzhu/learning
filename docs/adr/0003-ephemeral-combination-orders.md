# 3. 组合订单作为支付瞬态包装器 (Combination Order as Ephemeral Payment Wrapper)

用户在前端购物车合并多位持有人体检进行结算时，系统生成虚拟的组合订单（`combinationOrderCode`）；该组合订单仅在支付结算期内作为瞬态凭据存在，支付成功后即刻解体，不承担任何后续履约或售后职责。

## 背景与权衡

在企业体检业务中，员工常为多位家属同时选购体检并要求一键合并付款。若将合并购买的所有体检项持久化为一个拥有长久生命周期的“主订单”，将带来灾难性的状态爆炸：
- 某位家属改期或取消预约时，大订单状态陷入局部处理；
- 财务退款与供应商接口状态同步极其复杂。

## 架构决策

- **瞬态聚合收银**：组合订单（`combinationOrderCode`）仅用于收银台将多笔主订单的应付金额进行一次性聚合，调用招行/微信/支付宝等三方网关合并扣款。
- **支付后即刻解体**：
  - 用户端“我的订单”与后台管理系统仅呈现解体后的 **N 笔独立主订单**（各显各人姓名、各持一张预约单）。
  - 后续的改期、到检、取消预约及退款，均在各自的主订单和预约单上闭环流转，组合订单不再介入。
- **占容与超时释放**：
  - 购物车暂存时不占名额；
  - 下单时触发临时占容；
  - 若 15 分钟内未完成支付，定时任务自动取消待支付订单，释放分院排期容量，并将对应项重新回退至用户购物车。
- **物理清理时机**：购物车项仅在收到支付成功回调后方才执行物理清理（`DELETE`）。
