# 8. 加项包合并履约、权益到期换店拦截与双轨到检报告同步 (Bundled Fulfillment, Equity Expiry Guard & Dual-Track Status Ingestion)

体检履约链路确立“**主套餐与加项包合并原子交付（Bundled Atomic Fulfillment）**”、“**权益过期换店熔断拦截（Equity Expiry Guard）**”以及“**线上定时轮询拉取与线下 MIS 人工导入双轨状态同步**”机制。

## 背景与权衡

体检履约涉及多项异构医疗服务与外部异构机构的协同：
1. **加项包履约形态**：员工自选自费或积分兑换的加项包必须与公司统付的主套餐在同一天、同一家分院由医护人员统一采血、化验与仪器检查，不能在机构端拆散为多笔独立预约；
2. **换店与企业权益有效期的冲突**：体检属于企业团体福利，具有严格的福利生效期与截止期（Equity Validity Window）。换店依赖“先取消原预约、再选新店预约”的解耦动作；若用户在权益过期后申请换店取消，是否允许再次预约成为决定企业福利预算敞口的核心分水岭；
3. **异构机构的状态与成果交付**：民营连锁体检中心（爱康/美年等）具备 API 集成能力，而公立三甲医院多采用纸质总检、院内局域网隔离系统，无法主动通过 Webhook 回调推送数据。

## 架构决策

- **主套餐与加项包合并原子交付（Bundled Atomic Fulfillment）**：
  - 预约单（`Appointment`）是承载主套餐及全部自选加项包的唯一履约容器；
  - **线上民营机构**：通过直连 API 向机构锁单时，所有加项包作为附加项目（Sub-Items）随主套餐在**同一笔外部预约单**中打包推送，对应单一机构外部就检编号；
  - **线下公立医院**：运营导出对接名单时，主套餐与加项包列表合并为该持有人在 Excel 中的**单条聚合记录**交付医院，确保就检现场单人、单店、单次一站式完成所有检查项目。

- **权益过期换店熔断拦截（Equity Expiry Guard on Store Change）**：
  - 跨门店变更唯一标准路径为“**自主取消预约 ➔ 释放原店排期 ➔ 主订单恢复待预约 ➔ 重新选新分院预约**”；
  - **权益到期拦截门禁**：若持有人所属的企业体检权益已过截止日期（`equityEndDate < Today`），虽原预约单仍可取消，但随后的**新预约发起流程将被权益门禁严格拦截阻断**（即取消后不可再发起预约）；
  - **交互警示**：取消预约前台交互必须向用户明确提示该熔断风险（若权益已到期，取消原预约将导致彻底丧失体检资格）。

- **双轨到检与报告同步机制（Dual-Track Status Ingestion）**：
  - **线上机构（定时轮询拉取）**：后台通过定时任务（如 [`PullAppointJsonReportHandler`](file:///D:/coder/代码/体检/hmsc-innovate-jobs/src/main/java/com/cignacmb/statistics/job/handler/PullAppointJsonReportHandler.java)）主动轮询拉取各民营机构的到检名单与原版 PDF 报告文件（原生私有 JSON 指标拉取已弃用，统一由大模型 OCR 提取），自动完成状态流转：`预约成功 (02) ➔ 已到检 (04) ➔ 已出报告 (05)`；
  - **线下公立医院（MIS 运营导入）**：由运营人员在 `hmsc-web-mis` 后台批量导入医院返回的到检 Excel 名单与报告文件，或单笔录入核销并上传扫描件，人工驱动状态机推进至终态。

## 效果与影响

- **履约体验完整**：加项包合并交付确保了持有人在分院现场的就检闭环，避免了主套餐已检而加项包漏检的纠纷；
- **福利边界严明**：权益到期拦截门禁彻底守住了企业客户的体检预算敞口，杜绝超期恶意换店与违规履约；
- **业务落地包容**：双轨同步机制既发挥了民营机构 API 的自动化能效，又兼容了公立三甲医院传统离线运作的行业现状。
