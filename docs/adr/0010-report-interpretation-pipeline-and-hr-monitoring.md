# 10. 报告解读增值服务流水线、权益子产品导入与企业异常监控 (Report Interpretation Pipeline, Benefit Sub-Product Ingestion & HR Monitoring)

体检报告解读与增值服务体系确立“**全域大模型 OCR 统一指标结构化（供应商原生 JSON 轮询已弃用）**”、“**项目级普惠 AI 即时解读**”、“**C59/C24 异步三方医生解读流水线**”、“**权益子产品导入赋权（非商城销售）**”以及“**B端企业 HR 异常指标看板监控**”架构机制。

## 背景与权衡

体检报告交付是体检履约的终点，更是健康管理增值服务的起点：
1. **异构机构数据标准撕裂与原生 JSON 缺陷**：早期平台尝试轮询拉取民营机构的私有原生 JSON 指标，但各连锁品牌（爱康、美年、瑞慈等）数据结构互不兼容、字段频繁漂移且公立医院无法提供 JSON。维护 N 套私有 JSON 解析器导致代码严重臃肿与维护灾难，因此平台全面转向由大模型对统一 PDF 原件进行结构化抽取；
2. **即时与深度的服务冲突**：员工出报告后希望立刻看懂指标，而专科医生人工深度分析需要耗费医疗工时，无法做到实时秒级图文互动；
3. **专业解读服务的供给边界与属性**：深度医生解读（C59/C24）是高度专业化的医疗增值服务，平台确立其**不在电商商城（Shop）上架销售，而是专属于体检业务侧**；在企业导入体检权益（Product Package）时，作为该权益下的**子产品（Sub-Product）**直接导入赋权；
4. **重大阳性与企业关怀**：企业 HR 需要掌握团队整体健康画像与高危分布，但员工个人健康数据又受个人隐私保护法（PII）严格约束。

## 架构决策

- **全域大模型 OCR 驱动指标标准化（Unified LLM-OCR Ingestion, Native JSON Deprecated）**：
  - **统一收敛至 PDF + 大模型 OCR**：无论是线上民营机构还是线下公立医院，系统统一归集原版 PDF 报告文件，全部交由**大模型智能 OCR 管道**统一提取临床检测项目、实测值、单位、参考区间及异常偏离标识；
  - **原生 JSON 接口全面弃用**：正式废弃历史定时轮询拉取机构原生私有 JSON 的数据链路，彻底终结多供应商数据契约撕裂；
  - **入库归档至健康档案**：抽取后的标准 JSON 数据统一映射对齐平台标准医学字典，落地归档至健康档案系统（HMES）；
  - **外院自主上传隔离与正式解读附件边界**：用户在移动端自行拍照/上传的外院历史报告（Past Report），仅在个人端提供查看，**坚决不推送到健康档案系统，不参与正式体检报告的历年趋势比对**；但用户为发起正式 C24/C59 报告解读而随单上传的当次体检报告附件（`manualOrOrg=0`）除外，须与机构报告（`manualOrOrg=1`）合并（上限 30 份）统一调用 `uploadHmesFile` 归档至 HMES 供专科医生阅片。

- **普惠 AI / 在线客服 vs HMC 托管异步三方医生解读多轨并行**：
  - **外部小诺健康 AI 免登与在线客服**：即时 AI 报告解读（含心理咨询等多 Agent）通过国密免登跳转至外部「小诺健康 AI 平台」并由其凭短效令牌回查报告 PDF（详见 [ADR-0016](./0016-xiaonuo-ai-sso-privacy-gate-and-report-callback.md)）；实时人工在线咨询则经 AES-GCM 免登跳转保险在线客服（`BGJD-报告解读 / PTZX-普通咨询`）；平台内 `MEMBER_CONSULT_*`（`ConsultRecord`）专责症状导医与科室推荐，独立于报告解读工单；
  - **C24/C59 异步三方医生解读流水线（HMC 核心托管）**：
    - 深度医生解读并非即时聊天机器人，而是由 **HMC 核心托管（标识 `interpretReportId`）** 的异步工单制专业医疗分析，HMSC 侧作为门禁、HMES 附件归档与自动触发编排网关；
    - **按次核销与补传不重扣**：首次新建工单校验并扣减子产品剩余次数（`remaindCount > 0`），已有工单补充或修改附件不重复扣次；虽可由员工账号代家属提交与查阅，但工单严格映射归属真实持有人（`Holder`）的核心客户号（`hmcId`）；
    - **手动前置开放门禁（`anomlndexInterpreType`）**：支持项目级双策略开放申请入口——`01`（已到检 `04` 或已出报告 `05`）或 `02`（预约体检日当天及之后，允许用户不等机构回传即自行上传纸质报告发起解读）；
    - **四条件自动申请报告解读（`ReportInterpretationEvent`）**：当「项目开启电子授权书 + 授权书类型匹配 + 核心门店开启自动解读授权 + 套餐含可用 C24/C59 次数」四条件同时满足且持有人预约时完成授权签署，出报告（线上定时拉取或线下 MIS 上传）即自动触发提交解读工单，无需用户手动操作；
    - 外部专科医生核阅分析后，解读结论以标准结构化数据永久回写并挂载在当前体检权益与报告项下。

- **权益子产品导入赋权机制（Benefit Sub-Product Ingestion, Non-Shop）**：
  - **业务属性定性**：C24（基础咨询/解读）与 C59（深度专科报告解读）属于高度专业的医疗增值服务，**不在健康商城（Shop）面向个人作为零售商品上架销售**，专属于企业体检业务侧；
  - **导入随包赋权**：企业大客户在入驻配置体检方案时，该解读权益在**批量导入企业权益时作为产品包项下的子产品（Sub-Product）**直接导入赋权给员工；
  - **核销与页面跳转闭环**：
    - 员工出体检报告后，系统反查当前权益下是否包含有效的 C24/C59 子产品；若存在，在报告详情页展示解读入口并一键跳转至专业医生解读页面，激活第三方异步专业医生解读流水线；
    - **不可用前置条件**：若公司入驻导入时未包含该子产品权益，则员工无法使用医生解读服务。

- **B端企业 HR 异常指标看板监控（B2B HR Health Dashboard）**：
  - 平台不对个人端实施粗暴的重大阳性短信报警，而是面向企业客户开设**线下异常指标监控通知与企业 HR 健康管理看板**；
  - 企业 HR 依据脱敏与合规授权机制，在后台集中查看企业员工的异常指标分布与体检报告解读整体情况，为企业制定年度健康干预政策提供决策支持。

- **家庭报告账户共用查看（Family Report Aggregation）**：
  - 员工为家属购买的体检订单，出具报告后直接归集在员工本人账户体系下（`queryBothAppointReportList`）；
  - 员工可在移动端自由切换持有人查阅家属体检报告与指标结论，极大简化了家庭健康管理门槛。

## 效果与影响

- **全域数据结构化**：大模型 OCR 彻底消除了公立医院非结构化报告障碍，实现了全集团体检指标的大一统；
- **服务分层清晰**：免费即时 AI 解读负责“广度科普”，异步三方专家解读负责“深度研判”，各司其职；
- **业务边界严整**：确立了医疗增值服务“随权益子产品导入”而非“商城零售加购”的属性，保持了企业健康履约主线的严肃性；
- **B端价值延伸**：HR 监控看板提升了 HMSC 平台面向大客户雇主的 B2B 企业健康管理黏性。
