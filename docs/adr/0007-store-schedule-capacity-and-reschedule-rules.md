# 7. 分院排期容量、改期边界与超期释放规则 (Store Schedule, Capacity, Reschedule Boundaries & Overdue Release)

体检履约链路采用“**原分院改期约束（Same-Store Reschedule）**”、“**体检当日不对称改退（Day-of Cancellation/Reschedule Asymmetry）**”、“**线上实时/核心配额双轨容量**”以及“**超期未到检自动释放闭环**”机制，平衡机构履约成本与员工预约灵活性。

## 背景与权衡

体检与普通电商商品不同，具有强烈的线下时效性与医疗资源专用性：
1. **跨店改期的高复杂度**：各分院的医疗设备（CT、核磁、胶囊胃镜等）差异巨大。若允许跨分院改期，系统必须重新对主套餐与所有加项包执行交集重算，且涉及原机构释放占容与新机构占容的跨系统分布式事务，极易造成单边坏账与履约纠纷；
2. **体检日当天的资源空置损失**：体检中心在就检日清晨已完成试剂配发、采血管贴码与医护排班。若允许就检当天任意取消退约，将造成供应商严重的空置损失；但若完全锁定不允许任何变更，当员工突发不适时又缺乏人性化救济通道；
3. **未到检导致的死锁沉没**：员工预约后无故缺席（No-show），若不主动取消，预约单将永久停滞在“预约成功”，导致企业体检权益沉没、名额浪费。

## 架构决策

- **原分院同店改期约束（Same-Store Invariant for Reschedule）**：
  - 改期（`Reschedule`）严格限定在**原预约门店**范围内变更就检日期或时段；
  - 严禁在改期接口中变更分院；若用户确需更换门店，必须主动执行“**取消预约 ➔ 释放名额并恢复主单权益 ➔ 重新选店发起预约**”，以维持履约单状态机与供应链结算的强局部性（Locality）。

- **体检当日不对称改退策略（Asymmetric Day-of Policy）**：
  - **体检当天默认禁止取消**：体检日当天系统关闭用户端主动取消预约入口，保护机构已准备的医疗物资；
  - **体检当天允许改期**：为兼顾员工突发疾病、紧急出差等意外情况，系统在体检当天依然保留原店改期通道，允许延后改至后续可用日期。

- **线上实时 API 与核心手工配额双轨排期（Dual Capacity Sources）**：
  - **线上民营机构**：直接调用供应商直连 API 动态拉取实时日历与时段容量；
  - **线下公立医院**：由下游核心系统（HMSCS）集中配置机构排期与配额上限，提前预约期配置为 3~7 天；
  - **项目级屏蔽日（Project Blackout Dates）**：由 `hmsc-web-mis` 在企业项目（Project）维度叠加节假日或特殊封网屏蔽日，对员工端日历进行拦截；
  - **时间段控制（Schedule Period）**：支持项目级开关；机构支持且项目开启时细分时段（如 08:00-09:00），否则降级为全天不细分。

- **需协调排期客服特批流转（Coordination Required Approval Mode）**：
  - 日期标记为“需协调”时，触发客服特批流程；
  - 提交后直接生成 `申请成功 (01)` 状态的预约单，自动分流进入线下协调模式，由客服/运营人工与医院沟通加号加配额。

- **超期未到检自动取消闭环（Automated Overdue Cancellation）**：
  - 后台通过定时任务（`CancelOverdueAppointmentHandler`）结合法定节假日与工作日推算；
  - 对超过体检日仍未到检（No-show）的预约单自动触发取消，释放占容，并将主订单恢复为“待预约”状态，保障员工在权益有效期内仍可重新履约。

## 效果与影响

- **履约边界清晰**：彻底规避了跨店改期引发的加项包交集断裂与供应链对账异常；
- **兼顾供需利益**：体检日“禁退可改”平衡了机构医疗资源准备成本与员工履约救济诉求；
- **资源高效周转**：超期未到检自动释放闭环避免了名额与权益的死锁流失。
