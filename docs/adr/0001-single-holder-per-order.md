# 1. 单笔体检订单仅绑定单一持有人 (Single Holder per Order)

尽管底层数据库 `MEMBER_EWP_ORDER_HOLDER` 物理结构支持多持有人（1 对多），但在业务与系统设计上严格约束 **一笔主订单仅对应一个体检人（1 对 1）**。

## 背景与权衡

早期系统设计支持一笔主订单包含多个体检人（如家庭套餐）。但在实际履约过程中，多体检人带来了极高的状态复杂度：
- 部分体检人取消或改期导致主订单状态难以收敛
- 部分退款与财务对账逻辑分裂
- 外部体检供应商（爱康、美年等）回传到检与报告时无法原子化闭环整单

## 架构决策

- **严格 1:1 约束**：主订单与持有人严格保持一对一。
- **拆单处理**：多人员体检（如家庭套餐/批量购买）在下单时直接拆分为多个独立主订单。
- **生命周期独立**：每笔订单的预约、改期、取消与到检闭环彼此完全解耦，独立流转。
