## 二、前台五大核心页面主线与隐式上下文硬规则

### 2.1 员工体检（基准主线）

```text
企业项目落地页（选角色 / 新老流程）
  ▼
① 导航页（选权益 + 完善实名四要素 + 三项标的缓存态）
  ▼
② 套餐页（主干套餐单选互斥 00/02/03 + 0~N 加项包 + AI 推荐问卷 + 套餐对比 + 价格明细）
  ▼
③ 机构页（城市 → 品牌 → 门店筛选/VIP/提前天数/电子报告 → 门店卡与评分）
  ▼
④ 日期页（日历 → 时段[仅线上直连且开开关] → 报告类型 → 领取方式 → 同意书/承诺书）
  ▼
⑤ 二次确认 → ⑥ 支付弹窗（积分 / 微信 / 支付宝 / 一网通；15 分钟临时占容超时自动取消）
  ▼
⑦ 订单详情（按线上直连 vs 线下医院走双轨预约状态机）→ ⑧ 体检报告（列表/对比/解读）
```

**页面衔接 3 条硬规则（改造必保）**：
1. **上一页决定下一页的可选范围**：套餐 + 全部已选加项包会通过设备能力交集收窄机构页门店列表；机构是否线上直连 + `appointPeriodSwitch` 决定日期页是否展示「预约时间段」。
2. **改上游必须清空下游**：回导航页换权益/改套餐后，已选门店与日期失效；回机构页换门店后，日期与时段必须重选。
3. **提交卡点通常在前置导航页**：日期页提交不可点，多因权益过期（Equity Expiry Guard）、实名信息缺项或存在未支付订单限制（Pending Order），而非日期页本身异常。

### 2.2 家属体检（复用组件 + 隐式上下文）

家属体检复用员工体检页面，但存在 **5 处关键差异** 与 **3 条隐式规则**：

| 维度 | 员工体检 | 家属体检 |
| --- | --- | --- |
| **入口与上下文** | `entryCode=0001` | `entryCode=0002` **且必须同步设置 Vuex `flowMode=family`** |
| **导航页形态** | 权益行 + 三项标的 | 顶部家属标签栏 + 权益卡，切标签即切换 `Holder` 与权益 |
| **信息缺项拦截** | 红字提示 + 弹窗 | 约 2 秒 toast 提示，跳**整页**完善信息而非弹窗 |
| **结算口径** | 企业统付（常见应付 ¥0） | 家属产品包（`G`）企业不统付，自费或划扣员工本人积分（家属积分共济） |
| **门店范围** | 项目全部可用门店 | 受家属产品包与门店白名单约束，通常更少 |

**隐式上下文硬规则**：
- **路由参数与 Vuex `flowMode` 必须同时成立**：只改路由为 `entryCode=0002` 或只带 `mode=family` 而不置 `flowMode=family`，后续套餐/机构/日期页仍按员工流程取数。
- **切换家属标签即重置全部标的**：换家属 = 换持有人 + 换权益，已选套餐、门店、日期必须全部清空。

### 2.3 优惠套餐购买（双入口：体检人前置 vs 体检人后置）

两条入口的核心分水岭在于**何时确认体检人（Holder）**以及**是否存在门店上下文**：

| 维度 | 体检人前置 | 体检人后置 |
| --- | --- | --- |
| **入口路径** | 商品列表 → 商品详情 → 「立即购买」→ 前置导航页 | 落地页「一级页」（顶部「推荐机构 / 热门套餐」同页双页签） |
| **体检人确认时机** | 进套餐页**之前**（前置导航页选择/新增体检人） | **日期页**才补选/填写体检人，返回日期页回显 |
| **页面形态** | 顺序独立路由，无页签栏 | 一级页有双页签；点选门店或套餐后进入「二级页」，页签栏与城市筛选**整体隐藏** |
| **可选套餐数** | 由商品锁定（通常 1 个），仅可叠加项包 | 开放多套餐，支持「先店后包 / 先包后店」两条双向路线 |
| **排序交互** | 排序栏存在但仅 1 个套餐 | 一级为「默认排序」下拉；二级拆成「价格排序 / 销量排序」两个按钮 |

**双入口 6 条防踩坑硬规则**：
1. **一级与二级的分界是门店上下文，不是路由层级**：从机构页点门店进入时置 `ewp_from === 'choosesStore'` 并带入 `storeCode`，页签栏（`showTabBar=false`）与城市选择器随之隐藏；仅在一级页切换页签不写 `ewp_from`，仍按一级渲染。
2. **二级页各有唯一入口**：二级套餐页仅由「一级机构页选门店 → 确定」进入；二级机构页仅由「一级套餐页选套餐」进入。
3. **城市选择器随上下文整体隐藏**（非置灰）：进入二级页已携带门店或套餐上下文时不再展示城市筛选；PC 端无区县下钻。
4. **后置链路前两页全程不涉及体检人**：直到日期页才补齐体检人；前置链路在进入套餐页前必须已选定体检人。
5. **前置链路点击排序会重建列表上下文**：排序会重新拉取列表并改写路由上下文，易导致后续步骤失配，改造需重点规避。
6. **套餐详情科目表为异步加载**：改造若切换渲染方式需同步处理加载态。

### 2.4 报销双通道：体检代报销（`0005`）vs 积分报销（`0006`）

两者共享首页「健康服务专区」入口及收款/上传/提交成功组件，凭 `specialProjectCode` 分流（见 `new-mobile` / `new-pc` `expenseAudit.vue`）：

| 维度 | 体检代报销（`specialProjectCode=0005`） | 积分报销（`specialProjectCode=0006`，前台称「福利报销」） |
| --- | --- | --- |
| **领域归属** | `MedicalReimbursement`（含体检报销 `01` / 复检报销 `02`） | `PointsReimbursement`（代码内旧称 `isKPMG`） |
| **报销对象与标的** | 员工本人及家属；院外体检或异常复检（款项打给员工本人储蓄卡） | 仅限员工本人；个人抬头健康消费（单项体检/疫苗/牙科/眼科/健身等） |
| **申请步数** | 四步：基本信息 → 收款信息（7 项含证件）→ 影像上传 → 提交成功 | 三步：收款信息（5 项不含证件）→ 报销信息（积分类目+金额+单张发票）→ 提交成功 |
| **凭证结构** | 多文件影像（≤30 个，单个 ≤10M）；公司抬头初审后进入 `08` 寄原件 | 单张个人抬头发票，无原件寄送环节 |
| **列表数据源与单号** | `queryUserReimburseListNew` | `queryIntegralReimburseRecord`（单号前缀 `KBX`） |

**报销前端 4 条隐藏约束与已知缺陷**：
1. **详情页强依赖 Vuex 写入**：`#/expenseAudit` 详情数据全部读取 Vuex `expense.twoInfos`，仅能由列表页点「查看详情」写入；**直接访问或刷新页面会空白**。
2. **H5 报销记录页合并展示两套单据**：改造时不得按单号前缀（`KBX`）做互斥过滤。
3. **付款失败（`05`）原单改卡重推**：按 [ADR-0015](file:///D:/coder/代码/体检/docs/adr/0015-reimbursement-mutual-exclusion-all-or-nothing-and-in-place-retry.md)，改卡重提保持原单号不变、不解冻积分、跳过人工复审直回 `02-待付款`；须注意积分报销分支在部分旧端（`mobile`）的 `05` 改卡入口条件与 `new-mobile` 存在差异，改动前需核对对应端 `expenseAudit.vue`。
4. **已知表单缺陷（D4）**：修改收款账户时，若先选「开户城市」再选「银行名称」，只读展示框可能不刷新导致下一步无响应。

### 2.5 订单中心与扩展模块要点

- **订单中心（`#/record-new/:index`）**：双页签结构——「购买订单（`type 1`）」与「购物车（`type 2`）」；购物车加车不占容，为空时保留底栏 ¥0.00 与灰态「结算」。
- **团检报名（`entryCode=0030`）**：首页入口文案由「员工体检」切换为「团检报名」，强制收敛至线下团检白名单门店，日期页仅团检日（`GroupCheckDay / groupCheck=Y`）可选，到检时间字段为 `groupCheckUpTime`（区别于个人预约时间）。
- **智能选检扩展**：AI 套餐推荐支持「沿用上次测评 / 重新测评（8 题问卷或上传报告）」；套餐对比支持 2 个套餐并排比对与「仅看差异项」；企业健康承诺书含 11 题健康申报 + 手写签名随预约提交。

## 三、前后端状态码字典（改造对齐基准）

> **铁律**：主订单状态与预约单状态分属**两套独立码值且存在重号**（例如 `01` 在订单侧是「待支付」，在预约侧是「申请成功/受理中」）。任何前后端条件判断必须明确维度。

### 3.1 主订单状态（`Order`，来源：[ParamEnum.java](file:///D:/coder/代码/体检/hmsc-common-resource/src/main/java/com/cignacmb/hmsc/constant/ParamEnum.java#L14-L39)）

| 码值 | 后端枚举描述 | 业务含义 |
| --- | --- | --- |
| `01` | 待支付 | 已建单未付款（存在未支付单时触发重复下单拦截） |
| `02` | 已支付 | 款项已到账（或 0 元企业统付自动确立），持有待预约资格 |
| `03` / `04` | 已发货 / 已收货 | 商城实物商品物流履约态 |
| `05` | 已取消 | 未支付取消或超时关闭（释放 15 分钟占容与预冻结积分） |
| `06` / `07` / `08` | 退款中 / 退款成功 / 退款失败 | 退款链路状态（混合退款遵循回调驱动退积分） |
| `09` / `10` | 待审核 / 审核通过 | 需审核类订单状态 |

### 3.2 预约单状态（`Appointment`，来源：[ParamEnum.java](file:///D:/coder/代码/体检/hmsc-common-resource/src/main/java/com/cignacmb/hmsc/constant/ParamEnum.java#L492-L512)）

| 码值 | 后端枚举描述 | 线上直连 vs 线下医院语义差异 |
| --- | --- | --- |
| `01` | 申请成功 | 线下医院 / 特批协调排期提交后的待人工确认态（部分前台文案显示「受理中」，**不可当成预约成功**） |
| `02` | 预约成功 | 线上直连锁单成功，或线下医院客服确认排期完成 |
| `03` | 取消预约 | 释放机构档期，关联主订单恢复为待预约（受权益到期门禁约束） |
| `04` | 已到检 | 确立供应商采购结算里程碑（Check-in Settlement Milestone） |
| `05` | 已出报告 | 履约终态，报告归档至 HMES |
| `06` | 预约中 | 线上提交处理中间态 |
| `07` | 预约失败 | 线上直连锁单超时/售罄即时落标（Synchronous Failure Policy） |
| `08` / `09` | 改期中 / 取消中 | 变更在途态 |

### 3.3 档期日历不可选状态（4 类成因不可混用）

| 状态标识 | 含义 | 成因与业务语义 |
| --- | --- | --- |
| `RestDay` | 休息日 | 机构/门店公休不营业 |
| `Notopen` | 未开放 | 机构尚未放号（一般开放近一个月） |
| `Aboutt` | 已约满 | 当日 `Schedule Capacity` 余量为 0 |
| `Blackout Dates` | 项目屏蔽日 | 后台在企业项目维度配置的排期阻断日（如长假/封网日） |

### 3.4 报销单状态（体检代报销 & 积分报销共用）

| 码值 | 状态文案 | 关键流转说明 |
| --- | --- | --- |
| `01` | 审核中 | 提交后初审阶段（通常 5 个工作日） |
| `02` | 审核通过待付款 | 全额核准进入财务打款（含 `05` 原单改卡重推直回态） |
| `03` | 已付款 | 财务打款成功；积分报销同步由回调触发预冻结转实扣 |
| `04` | 已取消 | 申请取消；积分报销原路返还积分 |
| `05` | 付款失败 | 银行卡/开户行有误导致打款失败，触发原单改卡免复审重推 |
| `06` | 审核未通过 | 整单驳回（不支持部分核减）；积分报销原路返还积分 |
| `08` | 待寄送发票原件 | 仅**体检代报销公司抬头发票**初审通过后触发；积分报销无此环节 |

### 3.5 电子发票状态（来源：[InvoiceStatusEnum.java](file:///D:/coder/代码/体检/hmsc-service/hmsc-service/hmsc-edge-enterprise/src/main/java/com/cignacmb/enterprise/enumes/InvoiceStatusEnum.java)）

| 码值 | 状态文案 | 说明 |
| --- | --- | --- |
| `00` | 开票中 | 已提交开票申请，等待核心与税控回调 |
| `01` | 已开票 | 电子发票已开具并推送收票邮箱 |
| `02` | 已作废 | 原发票已作废 |
| `03` | 开票失败 | 开票异常失败 |
| `04` | 红字已开 | 已冲红开具红字发票 |
| `05` | 未开具 | 尚未申请开票（须同时满足无有效记录且无部分退款方为 `invoiceFlag=Y`） |

> 抬头类型（[InvoiceHeaderTypeEnum.java](file:///D:/coder/代码/体检/hmsc-service/hmsc-service/hmsc-edge-enterprise/src/main/java/com/cignacmb/enterprise/enumes/InvoiceHeaderTypeEnum.java)）：`00` = 公司（必填纳税人识别号），`01` = 个人/非企业单位。存在部分退款（`invoiceFlag=refund`）的订单禁止线上开票。

## 四、前台 UI / 代码词汇 ↔ 领域标准术语对照

| 前台文案 / 代码字段 | 领域标准术语（见 `CONTEXT.md`） | 改造注意事项 |
| --- | --- | --- |
| 体检人（`checkUpPerson`） | **Holder（持有人）** | 一笔主订单严格 1:1 绑定单一持有人 |
